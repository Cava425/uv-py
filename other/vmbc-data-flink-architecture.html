01定位与结论

这是一个面向查询的投影系统，不是业务主数据系统。 MySQL 保持权威写入；Flink 消费变更并补充关联快照，将可查询文档写入 Elasticsearch。 场景管理 ES 列表可承担复杂过滤和检索，详情、下载及强一致校验仍应回到 MySQL 业务链路。

职责拆分

两个实时 Job，各自维护一个投影切面

主数据 Job 更新文档主体和数据集关系；标签 Job 用关系表变更触发标签、标注人快照刷新。

恢复与补齐

回灌独立于实时流

有界 MySQL 游标扫描用于历史补数或重建。确定性文档 ID 让同一租户同一场景数据落到同一 ES 文档。

一致性模型

最终一致，不是跨系统事务

Checkpoint 管理 Flink 状态与 Source 进度；ES Bulk 写入没有与 MySQL、Kafka、Flink Checkpoint 组成原子事务。

文档基线说明： 本文按 2026-10-27 的当前工作区快照核对，包含尚未提交的工作区改动，不等同于已发布制品。 当前工作区 POM 显示版本 1.0.12、Java target 17；README 仍写 Java 8。 发布前应确认目标 Flink 集群的 JVM 版本与这组代码变更是否一致。

02总体架构与数据边界

实时变更由 Debezium/Kafka 提供；两条实时流在 Flink 内补充不同的 MySQL 关系快照。回灌 Job 则直接读取 MySQL，不经过 Kafka。

Flink 作业边界

三个入口独立提交、消费/读取方式不同：主数据实时、标签实时、场景数据回灌。作业间不共享 Flink 状态，也没有跨 Job 的原子更新。

读模型边界

ES 是由多条写入路径共同维护的投影。相同租户规则、索引名和文档 ID 是协作前提；ES 查询延迟与数据库主视图短暂不一致是设计属性。

为何分成两个实时 Job？ 主表和标签关系表拥有不同 Topic、更新频率和投影语义。标签变化无需等待主表变化即可刷新标签； 同时，标签快照批处理可以独立调节状态、查询批次与并行度。代价是同一文档可能被不同 Job 并发局部更新，需要审慎定义字段所有权。

04主数据实时流：CDC 到文档 Upsert

读取事件旧版 FlinkKafkaConsumer<String> 读取 Debezium JSON。
提取 after仅 c/u 进入投影；非法 JSON 抛异常，非写入事件输出空对象后被 Sink 跳过。
关联补充每条有效事件 JDBC 查询数据集版本关联，过滤 deleted=0。
写 ES用 lesseeCode:id 做 ID，Bulk 中提交文档部分更新 / upsert。

数据集关联查询是同步的逐事件 enrich

ScenarioDataDatasetRelationEnrichment 对每条带租户和主键的主表变更执行一次参数化 SQL， 输出 datasetRelations[]。这使每条主表事件能读取当时有效关系，并让空结果数组覆盖旧关系； 但也将 MySQL 查询量与 CDC 事件量直接绑定。

vmbc_scenario_data CDC → payload.after (c/u) → SELECT active dataset relations → buildScenarioDataDocument(...) → UpdateRequest(index, lesseeCode + ":" + id) .doc(document) .docAsUpsert(true)

删除边界

主数据 transform 当前只接受 c/u。物理删除事件没有构造成 ES Delete；逻辑删除更新会将 deleted 写入投影，但具体查询是否过滤仍由 ES 查询端负责。

关系变更边界

数据集关系表的独立变化不会触发本 Job。已有文档的 datasetRelations 可能保持旧值，直到主表再有变更或通过回灌/其他重建机制刷新。

05标签流：事件合并后刷新完整快照

标签事件不是逐条翻译为 ES 增删操作，而是“某个场景数据的标签快照需要刷新”的信号；刷新时 MySQL 的有效关系集合才是标签内容来源。

归一化变更c/u 从 after 取对象；d 从 before 取对象；只接收 SCENARIO_DATA。
按文档去抖Key 为 tenant:scenarioDataId；固定 processing-time 窗口保留最新事件。
按桶组批用租户和对象 ID hash 分桶；每桶达到 batch size 或 timer 到期就 flush。
批量构造快照一条参数化 IN 查询有效关系及标签，输出每个对象的标签和去重标注人。
关键实现

空快照也必须发出

查询前为本批每个 ID 初始化空 tags 与 annotators。关系被删除或查无有效标签时，空数组仍写回 ES，避免旧标签永久残留。

写入所有权

不 Upsert，避免产生残缺文档

标签 Sink 只局部更新现有文档，并设置 retryOnConflict(3)。ES 主文档仍由主数据流或回灌创建。

固定窗口从首个事件开始，不因后续事件而延长；它是处理时间合并，不是事件时间排序或严格静默窗口。 该 Job 只监听标签关系 Topic，标签主表自身的名称、类型、层级或删除变更不会触发相关场景数据刷新。

06历史回灌：有界游标扫描

回灌入口直接从 MySQL 读取有效场景数据，按 id > lastId ORDER BY id LIMIT batch 推进。每页分别批量读取标签快照和数据集关联，再将完整文档送入 ES。

扫描策略

当前固定租户 NIO、批次 100、并行度 1、起始 ID 0；END_ID=0 表示不限制结束 ID。

状态恢复

Source Operator State 保存 lastId。Checkpoint 恢复可以从最近保存的游标继续；无恢复状态重新提交会从配置常量重新扫描。

写入目标

当前代码常量目标是 vmbc_data_be_stg_scenario_data_query_v1，与 README/样例 Mapping 中的 test 索引名不同。

回灌不是无风险的“全量同步按钮”：执行前必须核对租户、目标索引、Mapping、覆盖策略和数据量。 同一固定 ID 重写可避免重复文档，但错误目标索引仍可能造成大范围覆盖或写入到错误环境。

07ES 文档模型与投影语义

文档 ID 为 {lesseeCode}:{scenarioDataId}。主数据流拥有基础字段、metadata 派生字段与数据集关系；标签流拥有 tags/annotators 局部字段。

ES 字段组上游来源写入策略用途/注意点
主字段
fileName、dataType、status、storagePath 等		vmbc_scenario_data主流部分更新 + Upsert列表检索、筛选、展示；字段空值通常会被省略，而不是显式清除。
时间字段
storageTime、createdAt、updatedAt		MySQL DATETIME按上海本地时间语义转 epoch millis需用真实 Connector/J、JVM 时区与 MySQL DATETIME 做端到端用例验证。
元数据派生字段
vehiclePlatform、modelType、vehicleId、ruleName、uuid、triggerTime		metadata.extra、metadata.manifest实时主流提取；trigger_time 纳秒除以 1,000,000匹配场景管理 ES 列表的元数据过滤契约；旧索引文档不会自动补齐。
datasetRelations数据集版本关系表主表事件时 JDBC 回查；回灌按页批查当前投影包含 datasetId 与 datasetVersionPkId；和查询端期望字段需统一。

Metadata 转换当前实现

支持 JSON 对象或 JSON 字符串；按 extra.vehicle_platform、extra.model_type、extra.vehicle_id、extra.rule_name、manifest.record_uuid 读取。trigger_time 以纳秒整数除以百万转换为毫秒。

实时与回灌投影不完全对称

实时 Sink 当前已提取 metadata 派生字段，但回灌主表 SQL 尚未 SELECT metadata，因此回灌不会构造这些派生字段。历史补数不能仅凭当前回灌流程保证补齐新 metadata 查询字段。

索引样例文件可辅助理解字段和分析器，但它不等于线上实际 Mapping。尤其是 dynamic 设置、nested 结构与字段类型，必须以部署目标索引为准。

08Checkpoint、Bulk 与故障恢复

层次当前机制保证与边界
Flink Checkpoint三个入口启用 checkpoint；Apollo 默认间隔 300,000 ms恢复 Flink 托管状态及支持的 Source 状态。Checkpoint 成功不代表 ES 与 Source 的外部效果组成原子事务。
Kafka Source显式支持 latest / earliest / group offsets首次启动偏移由模式决定；从有效 checkpoint 恢复时以恢复状态为准。自动提交配置不能替代 checkpoint 状态语义。
实时 ES Bulk最多 1,000 actions 或 5 秒 flush；指数退避，最大 5 次，初始延迟 200 ms重试后仍失败可将异常传回 Flink，触发 Job 失败与集群配置的恢复策略；具体退避次数/异常分类以运行时 Connector 为准。
文档幂等性tenant:id 固定 ID；主流 Update/Upsert，回灌 Index 覆盖降低同一变更重放造成的重复文档；不等于端到端 exactly-once，也不防止旧版本覆盖新版本。
重启策略作业代码未设置显式 Restart Strategy是否自动重启、间隔和次数上限由 Flink 集群/提交配置决定；检查 Dashboard restart count、attempt 和 checkpoint。
2026-10-27 运行现象： Dashboard 异常记录显示 ES Bulk 连接在 30 秒超时。配套监控中 Job Uptime 在约 12:00 归零， job_fullRestarts 从 68 增至 69，随后 Uptime 重新增长；这与 11:54:40 的异常时间相邻， 强烈支持作业随后发生了一次全量重启并恢复运行。该证据确认了重启现象，但未单独确认 ES 响应慢、网络链路还是代理为超时根因。

恢复后的数据可能从最近成功的 Checkpoint 重放。固定 ID 使主文档重放趋于覆盖同一文档；排查时仍需观察 Checkpoint 完成、Kafka lag、Sink Bulk 失败和 ES 写入队列，而不能只看提交计数日志。

09部署前置条件与可观测性

运行时依赖

应用 JAR 不是完整 Flink Runtime

  • Apache Flink 1.16.1；Kafka 与 Elasticsearch Connector 使用 provided，由提交/集群环境提供兼容版本。
  • ES 目标为 ES 8 时，需按兼容方案加载 ES7 Connector patch；避免原始 Connector 与 patch 重复加载。
  • 应用从 Apollo vmbc_data_flink 读取配置；数据库凭证使用通用 database.*。
  • 当前代码以 http 构造 ES Host 并配置 Basic Auth；需确认网络隔离或 TLS 终止边界。
资源与背压

数据路径会同步依赖 MySQL 与 ES

  • 主数据流每条有效事件单次 JDBC enrichment；数据库慢或连接池等待会直接拖慢算子。
  • 标签流以 bucket 聚合查询降低 SQL 次数；热点桶、批量尾延迟和状态大小仍需监控。
  • 连接池为 TaskManager JVM 级静态池，需按 TaskManager 数与池上限评估数据库连接总量。
  • 标签 enrichment 暂时关闭 chaining，利于分段观察反压，但会增加序列化和网络传输。

10方案亮点、难点与工作量

架构亮点
  • 读写职责分离：复杂检索落在 ES 投影上，MySQL 仍是权威数据源。
  • 稳定键与快照更新：固定租户 ID 避免重复建文档；标签删除通过重查快照和空数组清除旧值。
  • 对标签更新做减载：先短窗口合并、再按 bucket 批查，减少重复 SQL。
  • 实时与回灌解耦：历史数据通过独立有界 Job 补齐，避免把批处理塞进实时 Topic。
关键难点
  • 两个 Topic 对同一 ES 文档做不同字段的局部更新，需要处理事件顺序、重放和字段所有权。
  • Flink checkpoint 与 ES bulk 没有跨系统事务；失败后可能重放，需用确定性 ID、快照语义和监控降低风险。
  • 标签流同时包含 keyed timer、MapState、批量 SQL、空快照清理与冲突重试，状态恢复和边界测试复杂。
  • ES Mapping、后端查询 DSL、回灌目标索引、API 字段契约要持续一致；Connector 的 ES7/ES8 兼容属于部署难点。

11风险、差异与建议验证项

级别现状 / 风险建议
高 2026-10-27 发生 30 秒 ES Bulk 超时并伴随一次 Job full restart；当前证据无法区分 ES 性能、网络、代理或瞬时故障。 关联异常时间、ES 服务端 Bulk/线程池/GC、TaskManager 出站网络与代理日志；在证据明确前不要只靠扩大 timeout 或并行度掩盖问题。
高 主流使用部分更新；普通文本字段在源值为空时常被省略，ES 旧值可能残留。metadata 也采取缺失即不写。 定义字段清空语义；为“有值→null/空串/字段缺失”增加测试，必要时显式清空或改为带版本保护的完整替换。
高 实时主流已投影 metadata 派生字段，但 backfill SELECT 未包含 metadata；回灌无法补齐这些字段。回灌索引/批次与 README 仍不一致。 先统一实时与回灌投影、补充回灌参数校验，再对目标索引做 dry-run 与 mapping 检查。
中 数据集关系表变化、标签主表变化不会自动触发对应文档刷新；ES 读模型可能保留旧关系或旧标签定义。 评估关系表/标签表 CDC 扩展、按对象刷新任务、周期对账或版本化重建策略，并明确可接受的最终一致窗口。
中 README 写 Java 8、回灌 test 索引/批次 500；当前工作区 POM 为 Java 17，回灌常量为 stg 索引/批次 100。样例 Mapping 仍以 test 命名。 发布前统一 POM、README、运行镜像、提交命令和索引模板；区分“仓库样例”与“线上真实 Mapping”。
中 DATETIME 在 CDC 与 JDBC 回灌路径中分别编码/转换；回灌中间值再经过主 Sink 时间转换，存在时区语义二次处理的风险。 使用固定时区和已知 MySQL DATETIME 样本，分别验证 CDC、回灌写入 ES 的 epoch millis 与查询显示值。
中 ES Host 当前固定使用 HTTP，同时设置 Basic Auth。 确认网络隔离、TLS 终止及凭证传输边界；若需直连不可信网络，应改为 HTTPS 并验证证书。
规格对齐： 场景管理 API 已定义独立 ES 列表、标签值过滤、metadata 筛选和最终一致性边界； Flink 负责形成可检索投影，但 API 契约本身不能证明目标索引 Mapping、线上数据和历史回灌已全部满足。
